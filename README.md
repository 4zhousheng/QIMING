# QIMING
我的第一个仓库

前端是ai写的，后端的逻辑基本都是我手搓的

一开始我是打算做一个自己的小商城项目作为自己的第一个项目的

所以选择了“启明”作为这个仓库的名称

不过后来因为种种心理以及身体上的问题耽搁了这个项目，再加上我们的课程设计课程本身也要开发一个项目，于是我决定直接把项目改成我们的课程设计（其实也一点没改）

一开始，我只简单地想去做一个大家都会做的普通springBoot项目敷衍了事

不过后来随着我对这些代码的优化了解越来越多，学习到了更多的技术，我对这个项目的最终完成形态有了更深层次的期待。

比如redis啊，比如kafka啊，ElasticSearch啊，还有spring cloud alibaba啊，还有手搓一个某个模块的spring-boot-starter啊，写测试代码啊这些知识的实现现在我还没有做出来，只开了一个mvc分支作为前瞻版本

但是在这个mvc分支开发的过程中，我开始思考能不能通过某些手段来优化我的这个项目的性能，我的脑中开始绘制更大的蓝图

###我想要把这些想法都实现

在这个分支中我还是有很多遗憾的，比如很多高性能的技术，我都没有实现，比如对Result的滥用导致直接返回Http Code的时间几乎为0，这带来了很大的麻烦

即使后端大多都是我写的，还是不免用AI偷很多懒，比如生成日期的代码逻辑，这本应该是我自己写的，然而我的专业基础课学的可能相当糟糕，几乎是没有给我留下太多的这方面的技术的印象
另一个遗憾的是jwt密钥生成的逻辑也不是我写的
不过让ai写cos service的代码我倒是没有丝毫愧疚，毕竟这种交互逻辑是相当无脑的

谈谈自己在这个分支的收获吧，即使我不是第一次写这种mvc架构的小课程设计了，但是确实还是第一次使用Mybatis plus框架，这个期间也是写出了不少的石山逻辑，也被MP 的typeHandler和LambdaQueryWrapper不能混合使用的bug给搞得心态爆炸
并且我也是第一次这么详细地写出vo dto do的分层，也是第一次接触用jwt鉴权来结合的spring security
